## NETLIFY BLOBS BACKEND (NEW IN v3-7)

**Big architectural change.** Admin and Inventory edits now save GLOBALLY across all users.

### How it works

1. **On every page load,** `App.jsx` calls `paramsService.load()`. This GETs `/.netlify/functions/parameters` which returns saved overrides from Netlify Blobs storage as JSON.
2. **`paramsService` then MUTATES** the exported objects from `adminParams.js`, `inventory.js`, and `devices.js` in place. ES modules expose shared references, so this works — `calculations.js` keeps using its static imports but sees the live values without any refactor.
3. **Brief loading screen** shows while parameters fetch (~100-300ms typical).
4. **Local dev / no backend:** if the function returns 404 (e.g. running `vite dev` without Netlify Dev), `paramsService` falls back to bundled defaults and `_loadedFromServer = false`. Admin/Inventory pages display "Backend unreachable — save is disabled" banner.
5. **Admin clicks Save** → `paramsService.save(snapshot, password)` PUTs to `/.netlify/functions/parameters` with `x-solviva-edit-password` header containing `AUTH.editPassword`.
6. **Server-side function** validates the password against `process.env.VITE_SUPERADMIN_PASSWORD` (Netlify exposes all env vars to functions regardless of `VITE_` prefix), then writes to Blobs.
7. **Future page loads** by ANY user worldwide get the new values.

### Files

- **`netlify/functions/parameters.js`** — GET (public, no auth) returns saved blob JSON; PUT (auth via `x-solviva-edit-password` header) writes JSON to Blobs.
- **`src/lib/paramsService.js`** — Client-side service. `load()`, `save(snapshot, pw)`, `getSnapshot()`, `subscribe(fn)`, React hook `useParams()`. Crucial helper functions: `applyOverrides()` (mutates exports), `resetToDefaults()` (restores from `ORIGINAL` clone).

### Admin UI changes

- **Admin.jsx** — Save/Discard buttons at the bottom. "Edits are saved globally" info banner (when backend reachable) or "Backend unreachable — save is disabled" warning banner (when not).
- **Inventory.jsx** — Same Save/Discard pattern. "SESSION_WARNING" callout from earlier rounds is gone.
- **Both pages** receive `savingDisabled` prop from `App.jsx` based on `paramsLoadedFromServer`.

### Important caveat

- **`VITE_SUPERADMIN_PASSWORD` is in the client bundle** — anyone with browser dev tools can extract it. The PUT endpoint check is a useful sanity guard (random scrapers can't hit the API), but it's not strong security. If/when the user wants serious anti-tamper, we'd need to switch to a backend-only password (e.g. `EDIT_PASSWORD` without VITE prefix) and have admins enter it at Save time instead of relying on the cached `AUTH.editPassword`.

## SOURCE-OF-TRUTH MATH (v3 Excel mappings)

The user has the v3 Excel locally — `Solviva_Calc_v_B_3_0.xlsm`. Ask them to upload it to this Files folder if you need to verify math.

### Markup formula (used everywhere in v3)
```
adminPrice = supplierCost x 0.70 / (1 - BASELINE_RATE)
where BASELINE_RATE = Admin!A1 = 0.26144542543429433  (HARDCODED in workbook)
```
Implemented as `markup()` helper in `src/data/adminParams.js`.

### Roof Material (CALCULATOR M36 + AA34)
```
AA34 = IF(M36=2, 0,                      <- M36=2: no prep needed (Metal)
        IF(M36=1, Y6 * Admin!E54,         <- M36=1: Asphalt (P9,200/kWp)
                  Y6 * Admin!E55))        <- else: Concrete (P17,000/kWp)
```
Web: `state.roofMaterial` in {`'metal'` (DEFAULT, P0), `'asphalt'`, `'concrete'`}.

### Location (CALCULATOR M37 + Y39 + AA38)
```
AA38 = IF(AND(M37=2, Y39>0), Y39*Admin!E61 + Admin!E60,    <- Luzon >30km
        IF(M37=1, Z6*Admin!E57 + Admin!E56,                  <- Cebu (fixed + per-panel)
          IF(M37=3, Z6*Admin!E59 + Admin!E58, 0)))           <- Siargao
```
Web: `state.location` in {`'luzon'` (DEFAULT, P0 if `locationKm <= 30`), `'cebu'`, `'siargao'`}.

const server = createServer((req, res) => {
  let url = req.url === '/' ? '/index.html' : req.url;
  url = url.split('?')[0];
